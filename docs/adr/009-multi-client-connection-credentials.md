# ADR 009 — Multi-client connection credentials and assistant

**Status:** Accepted for EXP-2 implementation

## Context

ADR 005 made the authenticated gateway the only supported bridge from
tailnet/Open WebUI clients to the loopback llama.cpp backend. Migration 008
implemented one installation-wide fingerprint and one mode-0600 secret file.
That is fail-closed, but rotating a phone also disrupts Open WebUI and every
other client. It also cannot truthfully show which client is ready, revoked,
or recently used.

## Decisions

### D1 — One observed connection snapshot

`ConnectionSetupQueryService` composes model health/public alias, gateway
credential readiness, Open WebUI, Tailscale/DNS, Serve mappings, Funnel state,
exact local/tailnet URLs, and probe freshness without writing. It advertises
only:

- Open WebUI: `https://<dns-name>:8443/`;
- OpenAI base URL: `https://<dns-name>:10000/v1`;
- models: `<base>/models`;
- chat completions: `<base>/chat/completions`;
- model: the observed public alias, never a filesystem path.

`/api` is never presented as an OpenAI base URL. Unknown or stale observations
cannot render ready.

### D2 — Client credential identity and bounds

Migration 011 adds `connection_clients` and `connection_client_secrets`.
Client IDs are random lowercase UUID hex generated by an injected provider;
labels are user-facing metadata only, 1–80 Unicode characters after trimming,
unique case-insensitively among non-revoked clients, and never enter filenames.
The closed client kinds are `openwebui`, `pocketpal`, `openai`, `curl`, and
`sse`. Scopes are a canonical, comma-separated subset of
`models:list,inference:read,inference:stream`; unknown scopes are refused.
At most 32 non-revoked clients may exist.

Durable metadata contains client ID, label, kind, scopes, active fingerprint,
created/rotated/revoked/last-used timestamps, last endpoint class, and revision.
It never contains a secret, authorization header, URL/address history, model
history, body, prompt, completion, or response.

### D3 — Secret custody and one-time reveal

Each active or overlap secret lives in a separate app-owned mode-0600 file:
`connection-secrets/<client-id>-<generation>.secret`. Both path components are
validated generated identifiers; the label is never used. Creation returns
the plaintext secret exactly once from the command result. Listing, status,
JSON, logs, events, support bundles, and later reads return metadata only.
Existing secrets cannot be revealed; rotate instead. UI copy/reveal is
explicit, time-limited, cleared on page exit, and never echoed in feedback.
Python-memory erasure is not claimed.

Secret-file publication is create-no-replace with file and directory fsync.
If metadata commit fails, the newly-created file is removed. If durable
metadata exists but its file is absent or mismatched, the client is not ready
and repair is rotation/revocation—not regeneration by guesswork.

### D4 — CAS lifecycle and overlap rotation

Create, rotate, revoke, record-use, and emergency disable are revision-fenced.
Rotation creates a new generation before the transaction changes the active
fingerprint. The old generation is removed after commit by default. Optional
overlap is bounded to 1–900 seconds, off by default, records its expiry, and
never extends on retry. Authentication accepts the active fingerprint and an
unexpired overlap fingerprint using constant-time comparison. Expired overlap
is rejected even before cleanup.

Revoking one client invalidates and removes only its files. Emergency
**Disable all remote API access** atomically sets a global disabled record and
revokes every client before best-effort secret-file cleanup. It is available
even when llama.cpp, the gateway process, Tailscale, or Open WebUI is unhealthy.
Re-enabling remote access is not implicit; the user explicitly creates or
rotates a credential and enables sharing through its normal preview.

### D5 — Legacy migration

Migration 011 preserves migration-008 `gateway_credentials` bytes and creates
one `legacy-install` client metadata row only when the singleton exists. Its
fingerprint, scopes, timestamps, revoked status, and revision are copied; its
existing `gateway-credential` secret file is not read, exposed, renamed, or
rotated by migration. The legacy row resolves that fixed file through an
explicit `secret_storage = legacy-singleton` value. The migration is atomic,
forward-only, idempotent through `schema_migrations`, and preserves every v10
row. A revoked singleton remains revoked.

### D6 — Gateway authentication and usage receipts

The gateway resolves presented Bearer tokens against all eligible active/
overlap fingerprints and returns only the client ID principal. Authorization
then applies that client's scopes. A successful request may record
`last_used_at` plus the closed endpoint class `models`, `chat`, or `stream`;
the timestamp is throttled and failure to record never changes the request
result. No address, model, request ID, or body is durable.

### D7 — Guided probes are mandatory and bounded

The state machine checks: model healthy; credential usable; authorized local
probe passes; unauthorized local probe fails; Tailscale DNS ready; Serve maps
exact loopback gateway/Open WebUI ports; Funnel is off; authorized tailnet
models passes; then instructions render. A client is never marked tested from
health alone. The tailnet streaming probe uses a fixed non-sensitive prompt,
accepts one valid SSE event by deadline, discards its body, and persists only a
redacted terminal classification/freshness time.

### D8 — Versioned local client cards

Cards are bundled data with a schema version, closed client type, actual field
labels (Base URL, API Key, Model, streaming, timeout), and support class:
`hardware-tested`, `protocol-tested`, or `example-only`. The GUI never scrapes
client documentation. A hardware-tested claim requires candidate-bound client
name/version/device evidence; otherwise the card remains protocol-tested or
example-only.

### D9 — CLI and GUI safety

Default CLI JSON is redacted. `add-client` and `rotate-client` reveal a secret
only to an interactive controlling TTY; redirected/non-TTY output refuses
unless an explicit mode-0600 output file was reviewed in a future ADR. GUI
widgets call only composed connection services. Secret values never enter Tk
notices, clipboard feedback, durable events, or diagnostic logs.

## Rejected alternatives

- user labels in filenames;
- plaintext/encrypted secrets in SQLite;
- QR codes or persistent copy history;
- one global rotation for every client;
- readiness inferred from Tailscale/health alone;
- `/api`, raw port 8080, LAN binding, or Funnel instructions;
- automatic credential creation, sharing enablement, or update.

## Verification and evidence

Required deterministic gates cover v10→v11 preservation and interrupted
migration, CAS conflicts, bounds, create/rotate/revoke/overlap/disable-all,
constant-time fingerprint matching, absent/mismatched files, mandatory auth
negative probes, exact URLs/alias, `/api` and filesystem-path exclusion,
secret canaries across SQLite/log/events/support/argv/notices/default JSON,
Funnel refusal, bounded probe time/body, GUI/CLI parity, and clean wheel install.

PocketPal, Open WebUI, generic SSE, two-client independent revocation, and
tailnet positive/negative results remain physical evidence pending until run
from a second device against the exact candidate.
